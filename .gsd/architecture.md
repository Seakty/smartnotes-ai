# SmartNotes AI — Architecture Reference

> This file is the single source of truth for system design decisions.
> Read this before designing any new feature or writing any new service.

---

## Request lifecycle

```
Browser
  └─ React (Vite, port 5173 in dev)
       └─ Axios (with httpOnly cookie)
            └─ FastAPI (Uvicorn, port 8000)
                 ├─ CORS middleware (allows frontend origin)
                 ├─ Auth middleware (validates JWT from cookie)
                 ├─ Route handler (parse + delegate)
                 │    └─ Service layer (business logic)
                 │         ├─ SQLAlchemy async session → PostgreSQL
                 │         └─ Redis client (cache / session store)
                 └─ Pydantic response model (serialise + return)
```

---

## Authentication flow

1. User submits login form → `POST /auth/login`
2. Backend verifies password hash (bcrypt)
3. Backend creates JWT (payload: `user_id`, `exp`)
4. JWT set as `httpOnly; Secure; SameSite=Lax` cookie — NOT returned in body
5. All subsequent requests automatically include the cookie
6. `get_current_user` dependency reads cookie, decodes JWT, fetches user from DB
7. Logout → `POST /auth/logout` → clears the cookie server-side

**Why httpOnly cookie instead of localStorage?**
XSS attacks cannot read httpOnly cookies. localStorage is accessible to any JavaScript on the page.

## Database schema

### users

| Column          | Type                | Notes                |
| --------------- | ------------------- | -------------------- |
| id              | UUID (PK)           | generated by DB      |
| email           | VARCHAR(255) UNIQUE | indexed              |
| hashed_password | VARCHAR(255)        | bcrypt hash          |
| full_name       | VARCHAR(255)        |                      |
| created_at      | TIMESTAMP           | server default NOW() |
| updated_at      | TIMESTAMP           | auto-updated         |
| is_active       | BOOLEAN             | default true         |

### notes

| Column     | Type                 | Notes                        |
| ---------- | -------------------- | ---------------------------- |
| id         | UUID (PK)            | generated by DB              |
| user_id    | UUID (FK → users.id) | indexed, CASCADE DELETE      |
| title      | VARCHAR(500)         |                              |
| content    | TEXT                 | rich text (HTML from TipTap) |
| summary    | TEXT                 | nullable — filled by AI      |
| tags       | VARCHAR[]            | PostgreSQL array type        |
| is_pinned  | BOOLEAN              | default false                |
| created_at | TIMESTAMP            | server default NOW()         |
| updated_at | TIMESTAMP            | auto-updated                 |

**Relationships:**

- One user → many notes (1:N)
- Ownership enforced at service layer: every note query filters by `user_id = current_user.id`

## AI integration design

### Summariser

- Triggered manually: user clicks "Summarise" button in the UI
- Route calls `ai_service.summarise_note(note_id, user_id)`
- Service fetches the note, checks ownership
- Sends note content to Claude with a focused system prompt
- Saves the returned summary to `notes.summary` column
- Returns the updated note

### Smart tagger

- Triggered manually: user clicks "Suggest tags" button
- Same pattern as summariser
- Claude returns a JSON array of up to 5 tag strings
- Tags are written to `notes.tags` column (PostgreSQL array)
- Client renders them as dismissible pill badges

### Claude API call pattern (in services)

```python
from anthropic import AsyncAnthropic

client = AsyncAnthropic(api_key=settings.ANTHROPIC_API_KEY)

response = await client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=512,
    system="You are a helpful assistant that summarises personal notes concisely.",
    messages=[{"role": "user", "content": note.content}],
)
summary = response.content[0].text
```

| --------------------------- | ----- | -------------------------- |
| `rate:{user_id}:{endpoint}` | 60s   | Rate limiting AI endpoints |
| `session:{user_id}`         | 30min | JWT invalidation on logout |

## Error response format (consistent across all routes)

```json
{
  "detail": "Human-readable error message here"
}
```

FastAPI's default `HTTPException` produces this format automatically.
Do NOT wrap errors in custom envelopes — keep it simple and consistent.
